Práctica: Despliegue y seguridad de aplicaciones web

Configuración de Apache, autenticación, HTTPS, Docker Compose y monitorización

1. Objetivo de la práctica

Una pequeña empresa necesita desplegar sus aplicaciones web en un servidor Debian. El sistema deberá disponer de dos sitios web independientes, una zona privada protegida mediante autenticación, acceso HTTPS y mecanismos básicos de seguridad y monitorización.

Además, se deberá realizar un segundo despliegue utilizando Docker Compose.

El objetivo es poner en práctica los conocimientos adquiridos sobre administración de servidores web, configuración de Apache, seguridad y virtualización.

2. Requisitos previos

Para realizar la práctica necesitarás:

  • Una máquina virtual Debian con permisos de administración.
  • Apache HTTP Server.
  • Docker y Docker Compose.
  • OpenSSL.
  • Un navegador web y herramientas de terminal.

Comprueba que el sistema dispone de las herramientas necesarias antes de comenzar. Si falta alguna, realiza su instalación.

3. Preparación y configuración de Apache

Actividad 1. Comprobación inicial

Comprueba el estado del servidor Apache y verifica que se encuentra correctamente instalado y funcionando.

Revisa también los módulos disponibles y los sitios virtuales que están configurados inicialmente.

Actividad 2. Activación y configuración de módulos

Habilita los módulos de Apache necesarios para realizar las operaciones de reescritura de URL, configuración de cabeceras HTTP y conexiones seguras.

Configura una cabecera HTTP de seguridad y comprueba que el servidor la devuelve correctamente en sus respuestas.

Actividad 3. Creación de sitios virtuales

La empresa necesita disponer de dos sitios web independientes:

  • empresa.test: página corporativa.
  • tienda.test: página de la tienda.

Para ello deberás:

  1. Crear los directorios correspondientes para alojar ambas páginas web.
  2. Crear una página HTML diferente para cada sitio.
  3. Configurar un sitio virtual de Apache para cada dominio.
  4. Establecer correctamente los directorios raíz y las restricciones de acceso.
  5. Activar las configuraciones y comprobar que Apache no presenta errores.
  6. Configurar la resolución de los nombres de dominio en el equipo desde el que accedas.
  7. Comprobar que cada dominio muestra su propia página web.

Documentación: incluye las configuraciones de ambos sitios y capturas que demuestren que funcionan de manera independiente.

4. Autenticación y control de acceso

Actividad 4. Creación de una zona privada

La empresa necesita disponer de un espacio web al que solamente pueda acceder su personal autorizado.

Realiza las siguientes tareas:

  1. Crear un directorio privado dentro de la web corporativa.
  2. Añadir una página HTML que identifique claramente la zona privada.
  3. Crear un archivo de usuarios y contraseñas.
  4. Configurar la autenticación de Apache para proteger el directorio.
  5. Crear al menos dos usuarios diferentes.
  6. Comprobar el comportamiento del servidor con credenciales incorrectas y correctas.

Verifica que los usuarios no autenticados no pueden acceder al contenido protegido.

Documentación: explica cómo has configurado la autenticación y muestra las pruebas realizadas. No incluyas contraseñas reales en el informe.

5. Configuración de HTTPS

Actividad 5. Certificado digital y acceso seguro

La web corporativa debe permitir conexiones HTTPS.

Para conseguirlo deberás:

  1. Generar un certificado digital autofirmado para el dominio corporativo.
  2. Almacenar el certificado y la clave privada en una ubicación adecuada.
  3. Configurar un sitio virtual de Apache para atender las conexiones HTTPS.
  4. Configurar el acceso seguro a la zona privada.
  5. Comprobar que la web corporativa funciona mediante HTTPS.
  6. Verificar que la autenticación sigue funcionando al utilizar HTTPS.

Documentación: incluye la configuración del sitio seguro, explica el proceso de generación del certificado y aporta capturas de las pruebas realizadas.

6. Seguridad y mantenimiento

Actividad 6. Aplicación de medidas de seguridad

Revisa la configuración del servidor y aplica las medidas necesarias para reducir los riesgos de seguridad.

Como mínimo, deberás comprobar:

  • La protección frente al listado de directorios.
  • Las restricciones de acceso a los recursos privados.
  • Los permisos de los archivos y directorios de la aplicación.
  • La protección de la clave privada del certificado.
  • Las cabeceras HTTP de seguridad.
  • La validez de la configuración general de Apache.

Realiza una copia de seguridad de los archivos de configuración de Apache.

Documentación: describe las medidas aplicadas y explica qué problema de seguridad ayuda a evitar cada una.

7. Despliegue mediante Docker Compose

Actividad 7. Despliegue de una aplicación en un contenedor

La empresa solicita disponer de una segunda versión de su aplicación web desplegada mediante Docker.

Realiza las siguientes tareas:

  1. Crear un directorio de trabajo para el nuevo despliegue.
  2. Crear una página HTML que identifique la aplicación desplegada.
  3. Preparar un archivo compose.yaml para ejecutar un servidor Apache.
  4. Configurar la publicación de un puerto para acceder desde el exterior del contenedor.
  5. Montar el directorio de la aplicación como volumen.
  6. Configurar una política de reinicio adecuada.
  7. Iniciar el servicio y comprobar que funciona correctamente.

Actividad 8. Comprobación y análisis del despliegue

Realiza las siguientes pruebas:

  • Acceder a la aplicación desde el navegador.
  • Modificar el contenido de la página y comprobar que los cambios se reflejan.
  • Detener y volver a iniciar el servicio.
  • Consultar el estado y los registros del contenedor.
  • Comprobar qué sucede cuando el puerto elegido ya está ocupado.

Explica las diferencias entre el despliegue realizado directamente sobre Apache y el realizado mediante Docker Compose.

Documentación: incluye el archivo compose.yaml, las comprobaciones realizadas y una breve explicación de las características principales del despliegue.

8. Registros y monitorización

Actividad 9. Análisis de los registros de Apache

Comprueba cómo Apache registra las peticiones recibidas y los errores producidos durante el funcionamiento del servidor.

Realiza las siguientes tareas:

  1. Localizar los registros de acceso y de errores de los sitios virtuales.
  2. Consultar los últimos accesos registrados.
  3. Visualizar los registros mientras se realizan nuevas peticiones.
  4. Provocar diferentes situaciones de acceso para generar registros.
  5. Identificar las peticiones correctas, los accesos denegados y los recursos inexistentes.

Explica qué información contienen los registros y por qué es importante disponer de ellos para administrar un servidor web.

9. Pruebas finales

Actividad 10. Validación del sistema

Una vez terminadas todas las configuraciones, realiza una comprobación general del sistema.

Debes verificar que:

  • Los dos sitios virtuales funcionan de forma independiente.
  • La zona privada solicita autenticación.
  • Los usuarios autorizados pueden acceder y los no autorizados no.
  • La web corporativa funciona mediante HTTPS.
  • La configuración de Apache no presenta errores.
  • Las medidas básicas de seguridad están aplicadas.
  • La aplicación desplegada con Docker Compose funciona correctamente.
  • Los registros reflejan las peticiones realizadas durante las pruebas.

Si alguna comprobación falla, identifica el problema, explica su causa y documenta cómo lo has solucionado.

10. Informe que debe entregarse

El trabajo se entregará mediante un único informe en PDF que documente el proceso de configuración y las pruebas realizadas.

El informe deberá incluir los siguientes apartados:

  1. Portada: título de la práctica, nombre del alumno o alumna, módulo y fecha.
  2. Objetivos: descripción de los objetivos alcanzados.
  3. Entorno: versiones de Debian, Apache, Docker y herramientas utilizadas.
  4. Configuración de Apache: módulos, sitios virtuales y directorios web.
  5. Autenticación: configuración de la zona privada y usuarios creados.
  6. HTTPS: certificado digital y configuración del acceso seguro.
  7. Seguridad: medidas aplicadas y copia de seguridad.
  8. Docker Compose: configuración, ejecución y pruebas del contenedor.
  9. Registros: ejemplos de accesos y errores generados.
  10. Incidencias: problemas encontrados y soluciones aplicadas.
  11. Conclusiones: valoración del trabajo realizado.

Condiciones de entrega

  • Entrega un único archivo PDF.
  • Incluye capturas reales que demuestren el funcionamiento de los servicios.
  • Añade los fragmentos relevantes de los archivos de configuración.
  • Explica con tus propias palabras las decisiones tomadas.
  • No incluyas únicamente capturas: el informe debe contener explicaciones.
  • No incluyas contraseñas, claves privadas ni otros datos sensibles.
  • No expongas el servidor de prácticas directamente a Internet.
Importante

No se valorará únicamente que los servicios funcionen. También se tendrá en cuenta que las configuraciones estén correctamente realizadas, que las pruebas demuestren su funcionamiento y que el informe explique el trabajo desarrollado.
