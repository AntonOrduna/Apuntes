UD5. Programación de bases de datos

1. Introdución á programación de bases de datos

1.1. Que é a programación de bases de datos?

A programación de bases de datos consiste en utilizar instrucións e estruturas lóxicas para realizar operacións sobre a información almacenada nun sistema xestor de bases de datos (SXBD).

Ademais de almacenar información e permitir consultas, os sistemas xestores como MariaDB ofrecen mecanismos para executar código, automatizar operacións e implementar regras de negocio directamente no servidor.

Entre as súas principais aplicacións destacan:

  • Automatizar operacións habituais sobre as táboas.
  • Validar os datos antes de almacenalos.
  • Aplicar regras de negocio.
  • Realizar cálculos e transformacións de información.
  • Controlar operacións que afectan a varias táboas.
  • Executar tarefas de mantemento de maneira automática.
Idea clave: A programación de bases de datos permite trasladar parte da lóxica dunha aplicación ao propio servidor, reducindo a repetición de código e centralizando determinadas operacións.

1.2. SQL declarativo e SQL procedemental

SQL é unha linguaxe que permite traballar coa información dunha base de datos. Tradicionalmente, SQL é unha linguaxe declarativa: o usuario indica que resultado quere obter, pero non describe todos os pasos que debe seguir o sistema para conseguilo.

A programación procedemental incorpora elementos propios das linguaxes de programación, como variables, condicións, bucles e procedementos.

SQL declarativo SQL procedemental
Describe que operación se quere realizar. Define unha secuencia de operacións.
Utiliza instrucións como SELECT, INSERT ou UPDATE. Engade variables e estruturas de control.
Non require especificar o algoritmo de execución. Permite controlar a lóxica do programa.
É habitual nas consultas e manipulación de datos. É habitual nos procedementos e funcións.

Exemplo de SQL declarativo

A seguinte consulta solicita os alumnos que pertencen ao curso DAW1: 

SELECT *
FROM alumnos
WHERE curso = 'DAW1';

Indícase o resultado que se desexa obter, deixando que MariaDB determine como executar a consulta.

Exemplo de SQL procedemental

Un programa pode comprobar unha condición e executar diferentes instrucións segundo o resultado: 

IF total_alumnos > 30 THEN
    SET mensaje = 'Grupo completo';
ELSE
    SET mensaje = 'Hai prazas dispoñibles';
END IF;

Neste caso, o código establece unha condición e determina que instrución executar en función do seu resultado.

1.3. Programación no servidor MariaDB

MariaDB incorpora mecanismos que permiten almacenar e executar código no propio servidor de bases de datos.

Os principais elementos de programación son:

  • Procedementos almacenados: bloques de instrucións SQL que se gardan na base de datos e se executan cando se realiza unha chamada.
  • Funcións: programas que reciben parámetros, realizan operacións e devolven un valor.
  • Disparadores (triggers): bloques de código que se executan automaticamente cando se producen determinadas operacións nunha táboa.
  • Eventos: tarefas programadas para executarse nun momento determinado ou de maneira periódica.
Elemento Forma de execución Finalidade
Procedemento Mediante CALL Executar un conxunto de operacións.
Función Dentro dunha expresión SQL Obter un valor calculado.
Disparador Automaticamente ante un cambio nunha táboa Validar ou rexistrar modificacións.
Evento Segundo unha planificación temporal Automatizar tarefas periódicas.

1.4. Vantaxes da programación no servidor

  • Centralización: a lóxica común almacénase no servidor e pode ser utilizada por diferentes aplicacións.
  • Reutilización: un procedemento pode executarse tantas veces como sexa necesario.
  • Automatización: determinadas operacións poden executarse sen intervención directa do usuario.
  • Seguridade: pódese permitir que un usuario execute un procedemento sen concederlle acceso directo a todas as táboas implicadas.
  • Consistencia: as regras de negocio poden centralizarse para evitar implementacións diferentes en distintas aplicacións.

2. Automatización de tarefas mediante guións SQL

2.1. Que é un guión SQL?

Un guión SQL (script) é un ficheiro de texto que contén unha ou varias instrucións SQL organizadas para executarse nun sistema xestor de bases de datos.

Os guións permiten agrupar operacións e executalas de maneira ordenada, evitando ter que introducir manualmente cada instrución.

Poden utilizarse, por exemplo, para:

  • Crear bases de datos e táboas.
  • Inserir datos iniciais.
  • Crear usuarios e asignar privilexios.
  • Realizar operacións de mantemento.
  • Executar consultas e actualizacións.
  • Crear procedementos, funcións e disparadores.

2.2. Estrutura dun ficheiro SQL

Os ficheiros SQL utilizan normalmente a extensión .sql. Son ficheiros de texto que poden abrirse con editores de código ou ferramentas específicas de bases de datos.

Un guión pode conter comentarios, instrucións SQL e separacións entre diferentes bloques de operacións.

Exemplo: creación dunha base de datos

-- Creación dunha base de datos
CREATE DATABASE empresa;

-- Selección da base de datos
USE empresa;

-- Creación dunha táboa
CREATE TABLE departamentos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL
);

-- Inserción de datos
INSERT INTO departamentos (nome)
VALUES
    ('Administración'),
    ('Informática'),
    ('Comercial');

-- Consulta dos datos
SELECT * FROM departamentos;

Ao executar o ficheiro, MariaDB procesa as instrucións na orde na que aparecen.

2.3. Comentarios nos guións SQL

Os comentarios permiten documentar o código, explicar a finalidade das operacións e facilitar o mantemento dos ficheiros.

MariaDB admite diferentes formas de escribir comentarios:

Comentario dunha liña con dous guións

-- Este é un comentario

Comentario dunha liña con #

# Este tamén é un comentario

Comentario de varias liñas

/*
    Este comentario ocupa
    varias liñas.
*/
Boas prácticas: os guións SQL deben estar organizados e documentados. É recomendable incluír comentarios que identifiquen os bloques principais e expliquen as operacións máis importantes.

2.4. Instrucións secuenciais

Nun guión SQL, as instrucións execútanse normalmente de forma secuencial, seguindo a orde na que aparecen no ficheiro.

Cada instrución SQL remata habitualmente cun punto e coma (;), que indica o final da instrución. 

CREATE DATABASE biblioteca;

USE biblioteca;

CREATE TABLE libros (
    id INT AUTO_INCREMENT PRIMARY KEY,
    titulo VARCHAR(150) NOT NULL
);

INSERT INTO libros (titulo)
VALUES ('Bases de datos relacionais');

SELECT * FROM libros;

Neste exemplo, primeiro créase a base de datos, despois selecciónase, créase unha táboa, insírese un rexistro e finalmente realízase unha consulta.

3. Ferramentas para editar e executar guións

3.1. MySQL Workbench

MySQL Workbench é unha ferramenta gráfica que permite administrar bases de datos e traballar con instrucións SQL. Pode utilizarse para conectarse a un servidor MariaDB e executar consultas e guións SQL.

Entre as súas funcionalidades destacan:

  • Crear e modificar bases de datos e táboas.
  • Escribir e editar instrucións SQL.
  • Executar consultas e scripts.
  • Visualizar os resultados das consultas.
  • Consultar os erros producidos durante a execución.
  • Gardar e abrir ficheiros SQL.

Traballar co editor SQL

Unha vez establecida a conexión co servidor MariaDB, pódese abrir unha nova pestana de consulta SQL e introducir as instrucións que se desexan executar.

Workbench permite executar unha instrución concreta ou un conxunto de instrucións seleccionadas. Tamén permite gardar o código nun ficheiro con extensión .sql.

Importante: aínda que Workbench está deseñado principalmente para MySQL, pode conectarse a servidores MariaDB. Algunhas funcionalidades específicas de administración poden presentar diferenzas segundo a versión do servidor.

3.2. Editores de texto e código

Os guións SQL tamén poden crearse utilizando editores de texto ou editores de código independentes da ferramenta de administración da base de datos.

Algúns exemplos son:

  • Visual Studio Code.
  • Geany.
  • Kate.
  • Gedit.
  • Notepad++.

Estes editores permiten crear ficheiros SQL, aplicar resaltado de sintaxe, organizar o código e gardar os scripts para executalos posteriormente.

3.3. Execución desde a consola de MariaDB

MariaDB proporciona unha ferramenta de liña de comandos denominada mariadb, que permite conectarse ao servidor e executar instrucións SQL directamente.

Desde a máquina virtual Debian pódese acceder á consola mediante: 

mariadb -u usuario -p

O parámetro -u indica o nome do usuario e -p solicita o contrasinal.

Tamén se pode indicar directamente a base de datos á que se quere acceder: 

mariadb -u usuario -p empresa

Unha vez dentro da consola, pódense introducir instrucións SQL e executalas.

3.4. Execución de ficheiros SQL desde a consola

Ademais de introducir instrucións manualmente, a consola permite executar o contido dun ficheiro SQL.

Unha forma de facelo é mediante a redirección da entrada: 

mariadb -u usuario -p empresa < script.sql

Neste caso, MariaDB executa as instrucións almacenadas no ficheiro script.sql sobre a base de datos indicada.

Outra posibilidade é conectarse primeiro á consola e utilizar a instrución: 

SOURCE /ruta/ao/ficheiro/script.sql;

Esta instrución permite cargar e executar un ficheiro SQL desde unha sesión interactiva de MariaDB.

3.5. Comparación dos métodos de execución

Método Características
Workbench Entorno gráfico, edición de consultas e visualización dos resultados.
Consola interactiva Execución directa de instrucións mediante comandos SQL.
Ficheiro SQL Permite almacenar e reutilizar un conxunto de instrucións.
Execución mediante redirección Permite executar un script desde a terminal sen entrar previamente na consola.

4. Organización e boas prácticas dos guións SQL

4.1. Organización dos ficheiros

Cando se traballa con varios guións SQL, é recomendable organizar os ficheiros en directorios e utilizar nomes descritivos.

Exemplo de organización dun proxecto

proxecto_bbdd/
│
├── 01_creacion_bbdd.sql
├── 02_creacion_taboas.sql
├── 03_insercion_datos.sql
├── 04_consultas.sql
├── 05_procedementos.sql
└── 06_disparadores.sql

Esta organización permite identificar facilmente a finalidade de cada ficheiro e executar as operacións nunha orde determinada.

4.2. Boas prácticas de programación SQL

  • Utilizar nomes claros para os ficheiros e obxectos.
  • Documentar as operacións mediante comentarios.
  • Separar as diferentes tarefas en ficheiros cando sexa necesario.
  • Manter unha orde lóxica nas instrucións.
  • Comprobar os erros despois de executar os guións.
  • Evitar operacións destrutivas innecesarias.
  • Realizar copias de seguridade antes de modificar datos importantes.
  • Utilizar usuarios cos privilexios necesarios para cada tarefa.

5. Exercicios prácticos

Exercicio 1. Creación dun guión SQL

Crear un ficheiro denominado 01_creacion_empresa.sql que conteña as instrucións necesarias para:

  • Crear unha base de datos chamada empresa.
  • Seleccionar a base de datos.
  • Crear unha táboa denominada departamentos.
  • Definir os campos necesarios para identificar cada departamento.
  • Inserir varios rexistros.
  • Consultar os datos almacenados.

Incluír comentarios para identificar cada bloque de instrucións.

Exercicio 2. Execución con MySQL Workbench

Abrir o ficheiro SQL anterior mediante MySQL Workbench e executar as súas instrucións contra o servidor MariaDB da máquina virtual Debian.

Comprobar os resultados obtidos e identificar posibles erros de execución.

Exercicio 3. Execución desde Debian

Utilizar a consola de Debian para conectarse ao servidor MariaDB e executar un ficheiro SQL almacenado na máquina virtual.

Comprobar o resultado da execución mediante consultas SQL e comparar o procedemento coa execución realizada desde Workbench.

Exercicio 4. Organización de scripts

Crear unha estrutura de directorios para organizar diferentes ficheiros SQL dun mesmo proxecto.

Separar as operacións de creación da base de datos, creación de táboas, inserción de datos e consultas en ficheiros independentes.
