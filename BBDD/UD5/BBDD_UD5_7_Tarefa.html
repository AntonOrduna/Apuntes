Práctica: Programación en bases de datos

Unidade didáctica: UD5 – Programación en bases de datos

Contorno de traballo: MariaDB e MySQL Workbench

1. Obxectivo da práctica

Nesta práctica desenvolverás diferentes elementos de programación almacenada en MariaDB para automatizar tarefas, procesar información e controlar situacións de erro.

Traballarás con variables, funcións, procedementos, estruturas de control, eventos, disparadores, cursores e mecanismos de tratamento de excepcións.

O obxectivo é construír unha pequena solución de programación integrada nunha base de datos, demostrando o funcionamento dos elementos implementados.

2. Preparación do contorno

Crea unha base de datos denominada xestion_comercial que permita xestionar unha pequena actividade comercial.

A base de datos deberá incluír, como mínimo, as seguintes entidades:

  • Produtos: identificador, nome, prezo e stock.
  • Clientes: identificador, nome e correo electrónico.
  • Pedidos: identificador, cliente, data e estado.
  • Liñas de pedido: pedido, produto, cantidade e prezo aplicado.

Podes engadir outras táboas cando sexan necesarias para implementar os mecanismos de programación solicitados.

3. Variables e funcións

  1. Utiliza variables de usuario e variables locais en diferentes operacións SQL.
  2. Emprega funcións incorporadas de MariaDB para realizar operacións con cadeas, datas, valores numéricos e condicións.
  3. Crea unha función almacenada que realice un cálculo relacionado coa actividade comercial, por exemplo, calcular o importe dunha liña de pedido ou aplicar un desconto.
  4. Utiliza a función creada en consultas SQL e comproba os resultados obtidos.

4. Procedementos e estruturas de control

  1. Crea un procedemento almacenado para realizar unha operación habitual de xestión, como rexistrar un pedido ou consultar información dun cliente.
  2. Utiliza parámetros de entrada e, cando sexa necesario, parámetros de saída.
  3. Incorpora variables locais para almacenar e manipular información.
  4. Utiliza estruturas condicionais para controlar diferentes situacións.
  5. Inclúe polo menos unha estrutura repetitiva para realizar unha operación varias veces.
  6. Executa os procedementos e comproba os resultados obtidos.

5. Eventos programados

  1. Comproba o estado do planificador de eventos de MariaDB e configura o necesario para permitir a súa execución.
  2. Crea un evento de execución única asociado a unha data e hora determinadas.
  3. Crea un evento periódico que realice unha tarefa automática de mantemento ou actualización da información.
  4. Modifica a programación dun dos eventos.
  5. Desactiva e volve activar un evento.
  6. Consulta os eventos existentes e elimina os que xa non sexan necesarios.

6. Disparadores (triggers)

  1. Crea un disparador que valide os datos dun produto antes da súa inserción ou modificación.
  2. Define un disparador que actúe despois dunha operación de actualización.
  3. Crea unha táboa auxiliar para almacenar información de auditoría.
  4. Utiliza OLD e NEW para rexistrar os valores anteriores e posteriores dunha modificación.
  5. Implementa un disparador que rexistre a eliminación dun rexistro.
  6. Realiza operacións de inserción, modificación e eliminación para comprobar o funcionamento dos disparadores.

7. Cursores

  1. Crea un procedemento que utilice un cursor para percorrer os produtos ou os pedidos da base de datos.
  2. Declara o cursor mediante DECLARE CURSOR e utiliza OPEN, FETCH e CLOSE.
  3. Emprega variables locais para almacenar os datos de cada fila.
  4. Procesa os rexistros mediante unha estrutura repetitiva.
  5. Realiza unha operación ou cálculo sobre cada rexistro recuperado.
  6. Controla correctamente o final do percorrido.

8. Tratamento de excepcións e erros

  1. Incorpora controladores de condicións mediante DECLARE HANDLER nun procedemento almacenado.
  2. Utiliza un controlador CONTINUE e outro EXIT, comprobando as diferenzas no comportamento.
  3. Controla a condición NOT FOUND no procedemento que utiliza o cursor.
  4. Implementa o tratamento dun erro SQL específico mediante un código de erro ou un código SQLSTATE.
  5. Utiliza SIGNAL para xerar unha mensaxe de erro personalizada cando non se cumpra unha regra de negocio.
  6. Utiliza RESIGNAL para propagar unha excepción despois de realizar unha operación adicional de rexistro ou control.
  7. Realiza probas que permitan comprobar o comportamento dos diferentes controladores.

9. Integración da solución

Unha vez implementados os elementos anteriores, realiza unha proba global da base de datos.

  • Executa os procedementos e funcións creados.
  • Comproba a execución dos eventos programados.
  • Realiza operacións que activen os disparadores.
  • Verifica os rexistros almacenados nas táboas de auditoría.
  • Executa o procedemento que utiliza o cursor.
  • Proba situacións que provoquen erros e comproba o tratamento das excepcións.

Comproba que os diferentes mecanismos funcionan correctamente e que non se producen modificacións inconsistentes nos datos.

10. Entrega da práctica

A entrega será exclusivamente un documento PDF que recolla o traballo realizado.

O documento deberá incluír:

  • Unha breve presentación da base de datos e da solución desenvolvida.
  • Capturas de pantalla das instrucións SQL executadas e dos elementos creados.
  • Explicación dos pasos seguidos para implementar cada apartado.
  • Descrición do funcionamento dos procedementos, funcións, eventos e disparadores.
  • Explicación do uso dos cursores e dos mecanismos de tratamento de excepcións.
  • Capturas das probas realizadas, incluíndo resultados correctos e situacións de erro.
  • Unha conclusión breve sobre o traballo desenvolvido e as dificultades atopadas.
Importante: as capturas deben permitir identificar as instrucións executadas e os resultados obtidos. Non abonda con incluír imaxes do código: é necesario explicar que fai cada elemento e como se comprobou o seu funcionamento.

11. Criterios xerais de realización

  • A base de datos debe estar correctamente estruturada e conter datos suficientes para realizar as probas.
  • Os procedementos, funcións, eventos e disparadores deben estar correctamente definidos e funcionar.
  • Os cursores deben percorrer os resultados e finalizar correctamente.
  • Os erros e condicións especiais deben tratarse de maneira controlada.
  • As probas deben demostrar o funcionamento real das solucións implementadas.
  • O PDF debe estar organizado, ser lexible e incluír explicacións claras e capturas relevantes.
