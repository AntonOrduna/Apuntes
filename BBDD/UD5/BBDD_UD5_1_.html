UD5. Programación de bases de datos

Bloque 1. Introdución á programación e guións SQL

A programación de bases de datos permite automatizar operacións, organizar tarefas e incorporar lóxica de negocio directamente no sistema xestor de bases de datos.

Nesta unidade utilizaremos MariaDB, instalado nunha máquina virtual Debian, e MySQL Workbench como ferramenta de administración e edición de instrucións SQL.

Obxectivos do bloque
  • Comprender que significa programar dentro dunha base de datos.
  • Diferenciar SQL declarativo e SQL procedemental.
  • Identificar tarefas que poden automatizarse mediante guións.
  • Coñecer as ferramentas para editar e executar ficheiros SQL.
  • Crear e executar os primeiros guións SQL en MariaDB.

1. Introdución á programación de bases de datos

1.1. Que é a programación de bases de datos?

A programación de bases de datos consiste en utilizar instrucións e estruturas lóxicas para realizar operacións sobre a información almacenada nun sistema xestor de bases de datos (SXBD).

Nunha base de datos non só podemos almacenar información e recuperala mediante consultas. Tamén podemos definir operacións que realicen cálculos, comproben condicións, repitan tarefas ou respondan automaticamente a determinados acontecementos.

Por exemplo, nunha base de datos dunha academia podemos necesitar:

  • Calcular automaticamente o número de alumnos matriculados.
  • Comprobar se existen prazas dispoñibles nun curso.
  • Actualizar o estado dunha matrícula.
  • Rexistrar os cambios realizados sobre determinadas táboas.
  • Xerar información estatística de maneira periódica.

Estas operacións poden realizarse mediante instrucións SQL individuais, pero tamén podemos agrupalas en programas que se executen cando sexa necesario.

1.2. SQL declarativo e SQL procedemental

SQL é unha linguaxe principalmente declarativa. Isto significa que indicamos ao sistema xestor que resultado queremos obter ou que modificación queremos realizar, sen especificar todos os pasos internos necesarios para conseguilo.

Exemplo de SQL declarativo

Queremos consultar os alumnos matriculados nun curso:

SELECT *
FROM alumnos
WHERE curso_id = 1;

Indicamos que información queremos recuperar. MariaDB decide como executar internamente a consulta.

Pola contra, a programación procedemental permite especificar unha secuencia de instrucións que se executan seguindo unha lóxica determinada.

Neste tipo de programación podemos utilizar:

  • Variables para almacenar valores temporais.
  • Condicións para tomar decisións.
  • Bucles para repetir operacións.
  • Procedementos para agrupar instrucións.
  • Funcións para realizar cálculos e devolver resultados.
  • Controladores para xestionar situacións de erro.

Exemplo de SQL procedemental

O seguinte exemplo mostra unha estrutura condicional que poderemos utilizar posteriormente dentro dun procedemento almacenado: 

IF nota >= 5 THEN
    SET resultado = 'Aprobado';
ELSE
    SET resultado = 'Suspenso';
END IF;

Neste caso, o programa comproba unha condición e executa unha instrución diferente dependendo do resultado.

1.3. Programación no servidor de bases de datos

A programación pode realizarse no equipo cliente, mediante unha aplicación externa, ou directamente no servidor de bases de datos.

MariaDB incorpora mecanismos que permiten almacenar e executar programas no propio servidor. Entre eles destacan:

Elemento Descrición
Guións SQL Ficheiros que conteñen instrucións SQL que se executan de forma secuencial.
Procedementos almacenados Conxuntos de instrucións gardados na base de datos e executados mediante unha chamada.
Funcións Programas que realizan unha operación e devolven un valor.
Disparadores (triggers) Programas que se executan automaticamente cando se producen determinadas operacións sobre unha táboa.
Eventos Tarefas que o servidor executa automaticamente nun momento ou intervalo programado.

1.4. Vantaxes da programación no servidor

  • Automatización: permite executar tarefas sen que un usuario teña que repetir manualmente todas as operacións.
  • Reutilización: unha mesma operación pode definirse unha vez e utilizarse desde diferentes aplicacións.
  • Centralización: a lóxica de determinadas operacións permanece no servidor da base de datos.
  • Integridade: permite establecer comprobacións e regras para controlar as modificacións da información.
  • Seguridade: é posible conceder permisos para executar determinados procedementos sen proporcionar acceso directo a todas as táboas.
Importante: non toda a lóxica dunha aplicación debe trasladarse á base de datos. É necesario decidir que operacións deben executarse no servidor e cales corresponden á aplicación cliente.

2. Automatización de tarefas mediante guións SQL

2.1. Que é un guión SQL?

Un guión SQL é un ficheiro de texto que contén unha ou varias instrucións SQL. Estas instrucións poden executarse de maneira secuencial para realizar unha tarefa ou un conxunto de operacións.

Normalmente, os guións SQL gárdanse en ficheiros coa extensión .sql.

A diferenza dunha consulta individual, un guión permite agrupar varias operacións relacionadas e executalas conxuntamente.

2.2. Aplicacións dos guións SQL

Podemos utilizar guións SQL para diferentes finalidades:

  • Creación de bases de datos: crear unha base de datos e todas as súas táboas.
  • Carga de información: inserir rexistros iniciais mediante instrucións INSERT.
  • Configuración: establecer parámetros ou preparar os elementos necesarios para unha aplicación.
  • Administración: crear usuarios, asignar permisos e modificar estruturas.
  • Mantemento: executar operacións periódicas ou tarefas de actualización.
  • Programación: crear procedementos, funcións, eventos e disparadores.

2.3. Estrutura dun ficheiro SQL

Un ficheiro SQL pode conter instrucións de diferentes tipos. O servidor execútaas seguindo a orde na que aparecen, respectando as dependencias entre elas.

Exemplo: creación e preparación dunha base de datos

-- Creación da base de datos
CREATE DATABASE IF NOT EXISTS academia;

-- Selección da base de datos
USE academia;

-- Creación dunha táboa
CREATE TABLE IF NOT EXISTS cursos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    horas INT NOT NULL
);

-- Inserción de datos
INSERT INTO cursos (nombre, horas)
VALUES
    ('DAW', 200),
    ('DAM', 200),
    ('ASIR', 180);

-- Consulta da información
SELECT * FROM cursos;

Neste exemplo, o ficheiro realiza varias tarefas consecutivas:

  1. Crea a base de datos se non existe.
  2. Selecciona a base de datos de traballo.
  3. Crea unha táboa.
  4. Insire varios rexistros.
  5. Consulta os datos introducidos.

2.4. Comentarios nos guións SQL

Os comentarios permiten documentar o código e explicar a finalidade das instrucións. O servidor non os interpreta como operacións SQL.

MariaDB admite diferentes formas de introducir comentarios:

Tipo Sintaxe Descrición
Unha liña -- Comentario O comentario comeza con dous guións seguidos dun espazo.
Unha liña # Comentario Outra forma de introducir comentarios nunha liña.
Varias liñas /* Comentario */ Permite escribir comentarios que ocupen varias liñas.

Exemplo de documentación dun guión

/*
    Base de datos: academia
    Finalidade: almacenar información dos cursos
    Autor: Departamento de informática
*/

-- Crear a base de datos
CREATE DATABASE academia;

-- Seleccionar a base de datos
USE academia;

2.5. O punto e coma como delimitador

En SQL, o punto e coma (;) utilízase habitualmente para indicar o final dunha instrución. 

CREATE DATABASE academia;

USE academia;

SHOW DATABASES;

Cada unha destas instrucións remata cun punto e coma. Isto permite ao servidor identificar onde termina unha operación e comeza a seguinte.

Relación co SQL procedemental: cando posteriormente creemos procedementos e funcións, atoparemos instrucións que conteñen varios puntos e coma internos. Para iso utilizaremos o comando DELIMITER, que permite cambiar temporalmente o delimitador utilizado polo cliente SQL.

3. Ferramentas para editar guións SQL

3.1. MySQL Workbench

MySQL Workbench é unha ferramenta gráfica que permite administrar bases de datos e traballar con instrucións SQL. Aínda que o seu nome fai referencia a MySQL, tamén podemos utilizala para conectarnos a un servidor MariaDB compatible.

No noso contorno, Workbench estará instalado no equipo anfitrión e conectarase ao servidor MariaDB que se executa na máquina virtual Debian.

Entre as súas funcionalidades destacan:

  • Crear e editar consultas SQL.
  • Executar instrucións individuais ou varios comandos.
  • Visualizar os resultados das consultas.
  • Gardar e abrir ficheiros SQL.
  • Administrar bases de datos e táboas.
  • Consultar os erros producidos durante a execución.

3.2. O editor SQL de Workbench

Cando establecemos unha conexión co servidor MariaDB, podemos abrir unha pestana de consulta SQL.

Nesta pestana escribimos as instrucións que queremos executar. Workbench permite executar:

  • A instrución situada no cursor.
  • Unha selección de instrucións.
  • O conxunto de instrucións do editor.

Os resultados aparecen na zona inferior do editor, mentres que os erros e as mensaxes de execución se mostran no panel de saída.

3.3. Gardar e abrir ficheiros SQL

Para conservar os guións podemos gardalos en ficheiros coa extensión .sql.

Por exemplo, podemos organizar os ficheiros dunha práctica do seguinte xeito: 

practica_ud5/
|
|-- 01_creacion_bd.sql
|-- 02_insercion_datos.sql
|-- 03_consultas.sql
|-- 04_procedementos.sql
|-- 05_funcions.sql
|-- 06_triggers.sql
|
|-- README.txt

Esta organización permite separar as diferentes tarefas e facilita a reutilización e o mantemento dos guións.

3.4. Outros editores de texto

Os ficheiros SQL son ficheiros de texto plano, polo que tamén podemos editalos mediante outros programas:

  • Visual Studio Code.
  • Notepad++.
  • Gedit ou outros editores de Linux.
  • Kate.
  • Vim ou Nano desde o terminal.

Estes editores permiten escribir e organizar o código sen necesidade de manter unha conexión activa co servidor. A execución deberá realizarse posteriormente mediante unha ferramenta cliente.

4. Métodos de execución de guións SQL

Unha vez creado un ficheiro SQL, necesitamos envialo ao servidor MariaDB para que execute as instrucións que contén. Existen diferentes métodos para facelo.

4.1. Execución desde MySQL Workbench

Podemos executar un guión directamente desde o editor SQL de Workbench.

  1. Establecer a conexión co servidor MariaDB da máquina virtual Debian.
  2. Abrir un novo editor SQL.
  3. Abrir un ficheiro existente ou escribir as instrucións.
  4. Seleccionar as instrucións que queremos executar ou executar o guión completo.
  5. Comprobar os resultados e as posibles mensaxes de erro.
Importante: Workbench actúa como cliente. As instrucións SQL envíanse ao servidor MariaDB, que é o encargado de procesalas e executar as operacións.

4.2. Execución desde a consola de Debian

MariaDB proporciona unha ferramenta de liña de comandos chamada mariadb. Mediante ela podemos conectarnos ao servidor e executar instrucións SQL directamente.

Para iniciar unha sesión interactiva podemos utilizar:

mariadb -u usuario -p

O parámetro -u indica o usuario co que queremos conectarnos e -p solicita o contrasinal.

Tamén podemos indicar directamente a base de datos que queremos utilizar: 

mariadb -u usuario -p academia

Unha vez conectados, podemos introducir instrucións SQL de forma interactiva: 

MariaDB [(none)]> SHOW DATABASES;

MariaDB [(none)]> USE academia;

MariaDB [academia]> SHOW TABLES;

MariaDB [academia]> SELECT * FROM cursos;

4.3. Execución dun ficheiro desde a consola

Ademais de introducir instrucións manualmente, podemos executar directamente un ficheiro SQL.

Unha forma de facelo é utilizar a redirección da entrada estándar desde o terminal: 

mariadb -u usuario -p academia < script.sql

Neste caso, o cliente MariaDB le o contido do ficheiro e envía as instrucións ao servidor para a súa execución.

Tamén podemos conectarnos primeiro ao servidor e utilizar a instrución SOURCE: 

SOURCE /home/usuario/scripts/script.sql;

Esta instrución permite executar un ficheiro SQL desde unha sesión interactiva do cliente MariaDB.

Exemplo completo de execución

Supoñamos que temos un ficheiro chamado crear_academia.sql no directorio /home/usuario/scripts/.

Podemos executalo desde o terminal mediante:

mariadb -u usuario -p < /home/usuario/scripts/crear_academia.sql

O servidor recibirá as instrucións do ficheiro e executaraas seguindo a orde na que aparecen.

4.4. Comparación dos métodos de execución

Método Características Uso habitual
Workbench Editor gráfico, resultados visuais e xestión das conexións. Desenvolvemento e probas.
Consola interactiva Permite introducir instrucións directamente. Administración e comprobacións.
Execución dun ficheiro Procesa automaticamente as instrucións dun ficheiro SQL. Automatización e despregamento.
SOURCE Executa un ficheiro desde unha sesión interactiva. Execución de scripts xa preparados.

5. Boas prácticas na elaboración de guións SQL

Un guión SQL debe estar organizado e documentado para facilitar a súa comprensión, execución e mantemento.

  • Utilizar nomes de ficheiros descritivos.
  • Organizar as instrucións por finalidade.
  • Incluír comentarios que expliquen as operacións importantes.
  • Respectar a orde de creación dos elementos da base de datos.
  • Utilizar indentación para facilitar a lectura.
  • Comprobar os resultados despois da execución.
  • Evitar incluír contrasinais ou información sensible nos ficheiros.
  • Manter copias dos guións e controlar os cambios realizados.
Precaución coa execución repetida: non todas as instrucións SQL se poden executar varias veces sen consecuencias. Por exemplo, un INSERT pode introducir rexistros duplicados e un DROP TABLE pode eliminar información existente. É importante coñecer o efecto das instrucións antes de executar un guión.

6. Exemplo práctico: creación dun guión SQL completo

Imos preparar un ficheiro SQL que permita crear e configurar unha pequena base de datos para xestionar cursos dunha academia.

O ficheiro conterá a creación da base de datos, a creación dunha táboa, a inserción de información e unha consulta para comprobar o resultado.

Ficheiro: academia.sql

/*
    UD5 - Programación de bases de datos
    Exemplo de guión SQL
*/

-- Crear a base de datos
CREATE DATABASE IF NOT EXISTS academia;

-- Seleccionar a base de datos
USE academia;

-- Crear a táboa cursos
CREATE TABLE IF NOT EXISTS cursos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(50) NOT NULL,
    horas INT NOT NULL
);

-- Inserir información
INSERT INTO cursos (nombre, horas)
VALUES
    ('DAW', 200),
    ('DAM', 200),
    ('ASIR', 180);

-- Consultar os cursos
SELECT
    id,
    nombre,
    horas
FROM cursos
ORDER BY nombre;

Este exemplo permite comprobar como podemos agrupar diferentes operacións nun único ficheiro e executalas desde Workbench ou desde a consola de MariaDB.

Resultado esperado: ao executar o guión obteremos unha base de datos chamada academia, cunha táboa cursos que conterá tres rexistros.

8. Exercicios prácticos

Os seguintes exercicios permiten practicar os conceptos explicados neste bloque utilizando a máquina virtual Debian co servidor MariaDB e MySQL Workbench.

Exercicio 4. Comparación de ferramentas
