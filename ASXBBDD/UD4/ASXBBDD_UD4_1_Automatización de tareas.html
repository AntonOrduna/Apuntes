Automatización de tareas administrativas y herramientas

La administración de un sistema gestor de bases de datos implica realizar numerosas operaciones de mantenimiento, configuración, seguridad y supervisión. Muchas de estas operaciones se repiten periódicamente y pueden automatizarse mediante secuencias de comandos.

En este bloque se estudiará por qué es importante automatizar las tareas administrativas y qué herramientas proporciona MariaDB para crear, almacenar y ejecutar scripts SQL.

Objetivos del bloque
  • Comprender la importancia de automatizar tareas administrativas.
  • Identificar las operaciones que pueden automatizarse.
  • Conocer las herramientas disponibles para crear scripts SQL.
  • Ejecutar scripts desde MariaDB Workbench y desde la consola.
  • Diferenciar entre ejecución interactiva y no interactiva.

1. Introducción a la automatización de tareas administrativas

1.1. ¿Qué es la automatización?

La automatización consiste en utilizar instrucciones, programas o secuencias de comandos para realizar tareas sin necesidad de que un administrador tenga que ejecutarlas manualmente cada vez.

En la administración de bases de datos, estas tareas pueden incluir la creación de usuarios, la realización de copias de seguridad, la comprobación del estado de las tablas, el mantenimiento de registros o la eliminación de información antigua.

En lugar de ejecutar individualmente cada instrucción, el administrador puede preparar un script que contenga todas las operaciones necesarias y ejecutarlo cuando sea preciso.

Ejemplo: mantenimiento manual frente a automatizado

Imaginemos que una empresa necesita eliminar diariamente los registros temporales de una base de datos cuando tienen más de 30 días.

Sin automatización:

  1. El administrador se conecta a MariaDB.
  2. Selecciona la base de datos correspondiente.
  3. Ejecuta una consulta para localizar los registros antiguos.
  4. Ejecuta la operación de eliminación.
  5. Repite el proceso cada día.

Con automatización:

Se prepara una secuencia de comandos que realiza la eliminación. Posteriormente, se puede programar su ejecución para que se realice automáticamente cada día.

1.2. Ventajas de la automatización

La automatización ofrece diferentes ventajas en la administración de un sistema gestor de bases de datos:

Ventaja Descripción
Reducción de errores Se evita repetir manualmente operaciones que pueden provocar errores humanos.
Ahorro de tiempo Las operaciones repetitivas se ejecutan sin intervención constante del administrador.
Repetibilidad Una misma secuencia de instrucciones puede ejecutarse varias veces siguiendo el mismo procedimiento.
Disponibilidad Algunas tareas pueden ejecutarse fuera del horario habitual de trabajo.
Trazabilidad Es posible registrar las operaciones realizadas y consultar sus resultados.
Estandarización Se garantiza que diferentes administradores utilicen el mismo procedimiento.

1.3. Tareas administrativas susceptibles de automatización

No todas las operaciones administrativas tienen que ejecutarse manualmente. Muchas pueden prepararse mediante scripts y herramientas de planificación.

A. Copias de seguridad

Las copias de seguridad permiten recuperar la información cuando se produce un fallo, una eliminación accidental o un problema en el servidor.

Se pueden automatizar operaciones como:

  • Realizar una copia de seguridad completa de una base de datos.
  • Guardar las copias en un directorio específico.
  • Asignar nombres con la fecha y hora de realización.
  • Eliminar copias antiguas siguiendo una política de retención.
  • Registrar si la copia se ha realizado correctamente.

Ejemplo de copia de seguridad en MariaDB

La herramienta mariadb-dump permite exportar el contenido de una base de datos a un fichero SQL. 

mariadb-dump -u root -p empresa > empresa_backup.sql

El comando solicita la contraseña del usuario y genera un fichero con la estructura y los datos de la base de datos empresa.

B. Tareas de mantenimiento

Las tareas de mantenimiento permiten conservar el correcto funcionamiento del sistema gestor.

Algunas operaciones habituales son:

  • Comprobar el estado de determinadas tablas.
  • Analizar tablas para actualizar estadísticas.
  • Optimizar tablas cuando sea necesario.
  • Eliminar registros temporales u obsoletos.
  • Revisar el espacio ocupado por las bases de datos.

Ejemplo: comprobación de tablas

USE empresa;

CHECK TABLE clientes;
CHECK TABLE pedidos;

Estas instrucciones permiten comprobar el estado de las tablas indicadas. Su ejecución puede incorporarse a un procedimiento periódico de mantenimiento.

C. Comprobaciones y supervisión

El administrador también puede automatizar consultas destinadas a comprobar el estado del sistema:

  • Consultar el número de conexiones activas.
  • Comprobar la existencia de determinadas bases de datos.
  • Revisar el número de registros de una tabla.
  • Detectar valores que incumplan determinadas condiciones.
  • Comprobar la disponibilidad de determinados servicios.

Ejemplo: consultar conexiones activas

SHOW STATUS LIKE 'Threads_connected';

La consulta devuelve el número de conexiones actualmente abiertas en el servidor MariaDB.

D. Gestión de usuarios y permisos

La administración de usuarios también puede automatizarse. Por ejemplo, una empresa puede necesitar crear periódicamente usuarios para nuevas aplicaciones o aplicar permisos comunes a determinados perfiles. 

CREATE USER 'consulta'@'localhost'
IDENTIFIED BY 'ClaveSegura123';

GRANT SELECT ON empresa.*
TO 'consulta'@'localhost';

Estas instrucciones crean un usuario y le conceden permisos de consulta sobre las tablas de la base de datos empresa.

E. Registro de operaciones

También es posible automatizar el registro de determinadas operaciones administrativas para disponer de información sobre cuándo se ejecutaron y cuál fue su resultado.

Por ejemplo, se puede guardar en una tabla de control la fecha de una copia de seguridad, el usuario que la inició y el estado de la operación.

1.4. Clasificación de las tareas automatizadas

Según su frecuencia de ejecución, podemos clasificar las tareas administrativas de la siguiente manera:

Tipo Descripción Ejemplo
Puntuales Se ejecutan cuando aparece una necesidad concreta. Crear una base de datos para una aplicación.
Periódicas Se ejecutan siguiendo una frecuencia determinada. Realizar copias de seguridad cada noche.
Condicionadas Se ejecutan cuando se cumple una condición o sucede un evento. Registrar una modificación de un pedido.
De supervisión Comprueban periódicamente el estado del sistema. Comprobar el número de conexiones activas.
Idea importante

Automatizar no significa únicamente ejecutar instrucciones SQL de forma automática. También implica decidir cuándo ejecutarlas, con qué frecuencia, bajo qué condiciones y cómo comprobar que se han realizado correctamente.

2. Herramientas para crear y ejecutar secuencias de comandos

2.1. ¿Qué es una secuencia de comandos?

Una secuencia de comandos o script es un fichero que contiene un conjunto de instrucciones que se ejecutan siguiendo un orden determinado.

En MariaDB, los scripts SQL contienen instrucciones del lenguaje SQL que permiten realizar operaciones sobre las bases de datos y administrar el servidor.

Habitualmente se almacenan en ficheros con extensión .sql.

Ejemplo de script SQL

Contenido del fichero crear_empresa.sql:

-- Creación de la base de datos
CREATE DATABASE IF NOT EXISTS empresa;

-- Selección de la base de datos
USE empresa;

-- Creación de una tabla
CREATE TABLE IF NOT EXISTS departamentos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nombre VARCHAR(100) NOT NULL
);

-- Inserción de datos iniciales
INSERT INTO departamentos (nombre)
VALUES
('Administración'),
('Informática'),
('Comercial');

Al ejecutar el fichero se realizan, en orden, las operaciones de creación de la base de datos, creación de la tabla e inserción de los datos iniciales.

2.2. Herramientas disponibles

Existen diferentes herramientas para redactar y ejecutar scripts SQL en MariaDB. En este curso se utilizarán principalmente MariaDB Workbench y la consola de comandos.

A. MariaDB Workbench

MariaDB Workbench es una herramienta gráfica que permite conectarse al servidor, administrar bases de datos y ejecutar instrucciones SQL desde un editor.

Entre sus principales funcionalidades destacan:

  • Crear y editar instrucciones SQL.
  • Ejecutar una instrucción o varias instrucciones seleccionadas.
  • Ejecutar scripts completos.
  • Visualizar los resultados de las consultas.
  • Consultar los mensajes de error.
  • Guardar scripts en ficheros con extensión .sql.
Workbench y MariaDB

Aunque la herramienta se denomine MySQL Workbench, puede utilizarse como cliente gráfico para conectarse a un servidor MariaDB. El servidor empleado en nuestras prácticas es MariaDB, instalado en la máquina virtual Debian.

B. Consola de MariaDB

MariaDB proporciona una herramienta de línea de comandos que permite conectarse al servidor y ejecutar instrucciones SQL directamente.

Para acceder a la consola se utiliza el comando mariadb. 

mariadb -u usuario -p

Los parámetros utilizados son:

  • -u: indica el nombre del usuario.
  • -p: solicita la contraseña del usuario.

Una vez establecida la conexión, aparece el indicador de MariaDB, desde el que se pueden introducir instrucciones SQL. 

MariaDB [(none)]> SHOW DATABASES;

MariaDB [(none)]> USE empresa;

MariaDB [empresa]> SHOW TABLES;

MariaDB [empresa]> SELECT * FROM departamentos;

La consola es especialmente útil para la administración remota, la ejecución de scripts y la integración con herramientas del sistema operativo.

C. Editores de texto y código

Los scripts SQL también pueden redactarse mediante editores de texto o entornos de desarrollo.

Algunas herramientas habituales son:

  • Visual Studio Code.
  • Notepad++.
  • Geany.
  • Vim o Nano.

Estos editores permiten crear y modificar ficheros SQL sin necesidad de estar conectados al servidor. Posteriormente, el fichero puede ejecutarse desde Workbench o desde la consola.

Ejemplo: crear un script con Nano en Debian

Se puede crear un fichero SQL desde el terminal de Debian mediante el siguiente comando: 

nano crear_empresa.sql

Una vez abierto el editor, se escriben las instrucciones SQL. El fichero se guarda y queda disponible para ejecutarlo posteriormente desde MariaDB.

2.3. Ejecución interactiva de instrucciones

La ejecución interactiva consiste en introducir las instrucciones SQL directamente en una herramienta que mantiene una conexión activa con el servidor.

El administrador escribe una instrucción, la ejecuta y recibe inmediatamente el resultado.

Este método se puede utilizar tanto desde MariaDB Workbench como desde la consola.

Ejemplo de ejecución interactiva desde la consola

mariadb -u administrador -p

USE empresa;

SELECT * FROM departamentos;

SHOW TABLES;

Las instrucciones se introducen una a una y MariaDB devuelve el resultado de cada operación.

La ejecución interactiva resulta útil para:

  • Realizar consultas puntuales.
  • Probar instrucciones antes de incorporarlas a un script.
  • Comprobar errores y corregirlos.
  • Administrar el servidor de forma manual.

2.4. Ejecución no interactiva de scripts

La ejecución no interactiva permite ejecutar un conjunto de instrucciones almacenadas en un fichero sin tener que introducir manualmente cada una de ellas.

Este método es especialmente importante para la automatización, porque permite reutilizar scripts y ejecutarlos desde otros programas o herramientas de planificación.

MariaDB permite realizar esta operación de diferentes maneras.

A. Utilización de SOURCE

El comando SOURCE permite ejecutar un fichero SQL desde una sesión abierta de la consola de MariaDB.

Primero se establece una conexión: 

mariadb -u administrador -p

Una vez dentro de la consola, se ejecuta: 

SOURCE /home/usuario/scripts/crear_empresa.sql;

MariaDB lee el fichero y ejecuta las instrucciones que contiene.

Importante:

El comando SOURCE se ejecuta dentro de la consola de MariaDB, no directamente en el terminal de Debian. La ruta del fichero debe existir y el usuario del sistema operativo debe tener permisos para leerlo.

B. Redirección de entrada desde el terminal

Otra posibilidad consiste en ejecutar un fichero SQL directamente desde el terminal utilizando la redirección de entrada <. 

mariadb -u administrador -p empresa < crear_empresa.sql

En este caso:

  • mariadb inicia el cliente de línea de comandos.
  • -u administrador indica el usuario de conexión.
  • -p solicita la contraseña.
  • empresa indica la base de datos inicial.
  • < crear_empresa.sql envía el contenido del fichero como entrada.

También se puede indicar una ruta completa: 

mariadb -u administrador -p empresa \
< /home/usuario/scripts/mantenimiento.sql

C. Ejecución mediante tubería

También se puede enviar el contenido de un fichero a MariaDB mediante una tubería utilizando el comando cat. 

cat mantenimiento.sql | mariadb -u administrador -p empresa

El funcionamiento es similar al de la redirección de entrada: el contenido del fichero se envía al cliente de MariaDB para su ejecución.

2.5. Comparación de los métodos de ejecución

Método Desde dónde se ejecuta Uso principal
Ejecución interactiva Workbench o consola MariaDB Consultas y administración manual.
SOURCE Consola MariaDB Ejecutar un fichero SQL dentro de una sesión.
Redirección < Terminal Debian Ejecutar un fichero SQL desde el sistema operativo.
Tubería | Terminal Debian Enviar la salida de otro comando a MariaDB.

2.6. Organización y mantenimiento de los scripts

Cuando se trabaja con diferentes scripts SQL, es recomendable mantener una organización clara de los ficheros.

Por ejemplo, se puede crear un directorio específico para almacenar las secuencias de comandos administrativas: 

mkdir -p ~/scripts/mariadb

cd ~/scripts/mariadb

nano crear_base_datos.sql
nano mantenimiento.sql
nano usuarios.sql
nano consultas_control.sql

Una posible organización sería: 

scripts/
└── mariadb/
    ├── crear_base_datos.sql
    ├── usuarios.sql
    ├── mantenimiento.sql
    ├── consultas_control.sql
    └── copias_seguridad.sh

Es conveniente utilizar nombres descriptivos, incluir comentarios y mantener copias de las versiones anteriores de los scripts.

2.7. Buenas prácticas al ejecutar scripts

La automatización permite ejecutar muchas operaciones rápidamente, pero también puede provocar problemas si los scripts no están correctamente preparados.

  • Comprobar las instrucciones: revisar el contenido antes de ejecutar operaciones que puedan modificar o eliminar información.
  • Utilizar usuarios adecuados: ejecutar cada script con los permisos mínimos necesarios.
  • Realizar copias de seguridad: proteger los datos antes de realizar modificaciones importantes.
  • Documentar los scripts: añadir comentarios que expliquen su finalidad y funcionamiento.
  • Controlar los errores: revisar los mensajes devueltos por MariaDB después de ejecutar las instrucciones.
  • Evitar contraseñas visibles: no incluir contraseñas directamente en los comandos o scripts.
  • Probar antes de automatizar: comprobar el funcionamiento manualmente antes de programar ejecuciones periódicas.
Seguridad en la ejecución de scripts

Un script puede contener operaciones destructivas como DROP DATABASE, DROP TABLE o DELETE. Si se ejecuta automáticamente sin comprobaciones, puede provocar pérdidas de información.

Por ello, es fundamental revisar los permisos, validar las instrucciones y disponer de copias de seguridad recuperables.

4. Ejercicios prácticos de aprendizaje

Los siguientes ejercicios permiten poner en práctica los conceptos explicados en este bloque utilizando el servidor MariaDB instalado en Debian y la herramienta Workbench.

Ejercicio 1. Identificación de tareas automatizables

Una empresa dispone de una base de datos que contiene información sobre clientes, pedidos, empleados y productos.

Se necesita identificar qué operaciones administrativas podrían automatizarse y justificar su utilidad.

  1. Identificar cinco tareas administrativas que puedan automatizarse.
  2. Clasificarlas según sean puntuales, periódicas o condicionadas.
  3. Indicar qué herramienta podría utilizarse para cada tarea.
  4. Explicar qué ventajas aportaría su automatización.

Ejercicio 2. Creación de un script SQL

Crear un fichero llamado centro.sql que contenga las instrucciones necesarias para:

  1. Crear una base de datos llamada centro.
  2. Seleccionar dicha base de datos.
  3. Crear una tabla llamada alumnos.
  4. Definir los campos identificador, nombre y correo electrónico.
  5. Insertar al menos tres registros de ejemplo.
  6. Consultar todos los registros insertados.

Ejercicio 3. Ejecución desde Workbench

Utilizar MariaDB Workbench para abrir y ejecutar el fichero centro.sql.

  1. Abrir el fichero desde el editor SQL.
  2. Ejecutar las instrucciones.
  3. Comprobar que la base de datos se ha creado correctamente.
  4. Consultar el contenido de la tabla.

Ejercicio 4. Ejecución desde la consola

Utilizar el terminal de Debian para ejecutar el mismo fichero SQL mediante dos procedimientos diferentes:

  1. Acceder a la consola de MariaDB y ejecutar el fichero mediante SOURCE.
  2. Salir de la consola y ejecutar el fichero utilizando la redirección de entrada <.
  3. Comprobar que ambos procedimientos ejecutan las instrucciones correctamente.
  4. Comparar las diferencias entre los dos métodos.

Ejercicio 5. Copia de seguridad desde el terminal

Realizar una copia de seguridad de la base de datos centro utilizando mariadb-dump.

  1. Generar un fichero SQL con la copia de seguridad.
  2. Comprobar que el fichero se ha creado.
  3. Consultar su contenido.
  4. Crear una segunda base de datos para realizar una prueba de restauración.
  5. Restaurar la copia de seguridad en esa segunda base de datos y comprobar sus tablas y registros.
Resultado esperado

Al finalizar estos ejercicios, el alumnado debe ser capaz de identificar tareas administrativas automatizables, crear ficheros SQL, ejecutarlos desde diferentes herramientas y realizar una copia de seguridad básica mediante la consola de Debian.
